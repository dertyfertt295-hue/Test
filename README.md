# Лума 0.5.1 — Android-чат с Iskra AI

Нативный интерфейс на Kotlin, Jetpack Compose и Material 3. Ассистент представляется как **Iskra AI**; доступны три модели на выбор — A-4.5, V-4.4.1 и S-4.5. Интерфейс на английском, русском и испанском.

## Установка

1. Установите `Luma-0.4.1-debug.apk` поверх предыдущей версии. Пакет и подпись сохранены, удалять старую версию не нужно. Минимальная ОС — Android 8.0.
2. Откройте приложение и войдите через Google.
3. Отправьте сообщение.

Ключ доступа встроен в приложение — вводить ничего не нужно.

## Вход через Google

Без входа приложение не открывает чат: экран входа — это всё приложение, а не баннер поверх него. Используется базовый `GoogleSignIn` из Play services: запрашиваются только id, имя и адрес почты, они сохраняются в приватных SharedPreferences на устройстве и больше никуда не передаются.

### OAuth-клиент обязателен

Даже базовому входу без ID-токена нужен зарегистрированный **Android**-клиент OAuth в Google Cloud. Без него Play services возвращает `ApiException` со статусом 10 (`DEVELOPER_ERROR`) и приложение показывает «Приложение не настроено для входа через Google».

В проекте Google Cloud должен быть OAuth-клиент типа Android с парой:

```
Package name:  app.luma.chat
SHA-1:         отпечаток ключа, которым подписан APK
```

Отпечаток текущей отладочной подписи — `E8:94:3F:67:1E:93:28:97:71:85:37:3C:57:AA:2A:F1:61:7B:7A:06`. Получить его для другого ключа:

```powershell
keytool -list -v -keystore <путь к keystore> -alias <алиас>
```

Сборка на другой машине или подпись релизным ключом дают другой отпечаток — для каждого нужен отдельный OAuth-клиент, иначе снова статус 10. Client ID никуда в код не вставляется: при базовом входе сопоставление идёт по паре «пакет + отпечаток».

Пока проект в режиме **Testing**, входить могут только аккаунты из списка **Test users** на экране согласия.

Это клиентская проверка, а не подтверждённая сервером личность: токен не запрашивается и не проверяется. Если понадобится доказывать бэкенду, кто пользователь, нужно перейти на Credential Manager с ID-токеном и завести дополнительно Web client ID.

«Выйти из аккаунта» очищает локальную запись и сбрасывает выбор аккаунта в Play services. Диалоги при этом остаются на устройстве.

## Сервер на ПК

История чатов хранится на домашнем ПК, отдельно для каждого Google-аккаунта, чтобы после выхода из аккаунта или переустановки приложения она восстанавливалась. Сервер лежит в `../IskraServer`.

Это Node + SQLite, по одной базе на аккаунт: папка называется SHA-256 от идентификатора Google-аккаунта, внутри `history.sqlite` с текущим состоянием и последними тридцатью версиями. Node положен рядом (`runtime/node.exe`), в системе ставить ничего не нужно.

| Команда | Что делает |
| --- | --- |
| `start.ps1` | Запускает сервер, если он ещё не запущен |
| `stop.ps1` | Останавливает |
| `open-firewall.ps1` | **Нужен запуск от администратора.** Открывает входящий TCP 8443 |
| `install-autostart.ps1` | Ярлык автозапуска при входе в Windows |
| `export.ps1` | Выгружает историю всех аккаунтов в JSON |

Связь — HTTPS с самоподписанным сертификатом и токеном в заголовке `Authorization`. Телефон доверяет ровно одному сертификату: он вшит в приложение (`res/raw/sync_server.pem`) и сверяется при каждом соединении. Поэтому проверка имени в сертификате отключена намеренно — подойти может только этот сертификат, каким бы адресом ни пользовался телефон, а привязка к имени ломалась бы при каждой смене домашнего IP.

Защита сознательно простая: это личный сервер для одного человека. Токен один на всё, ротации нет, учёта попыток входа нет.

### Как телефон находит ПК

Порядок адресов: сначала введённый в настройках, затем публичный и локальный, вшитые при сборке. Тот, что ответил последним, пробуется первым, так что обычный случай — один запрос.

Домашний IP со временем меняется, поэтому адрес можно вписать в настройках («Адрес ПК») без пересборки приложения. Принимаются `1.2.3.4`, `1.2.3.4:9000`, имя хоста или полный URL; порт по умолчанию 8443. Пустое поле означает «использовать вшитые адреса». Адрес хранится на телефоне и не синхронизируется — он описывает, как дойти до ПК именно отсюда.

### Слияние

Телефон держит локальную копию и базу последней подтверждённой версии. При синхронизации он берёт состояние сервера, накладывает свои изменения относительно базы и отправляет обратно с номером ревизии; сервер отвечает 409, если за это время появилась другая версия, и попытка повторяется. Удаление побеждает устаревшую копию, поэтому телефон, пролежавший неделю в ящике, не воскрешает удалённые диалоги. Правки, набранные пока запрос был в пути, не теряются.

Без связи изменения копятся на телефоне: в настройках видно состояние («Сохранено на ПК» / «Ждёт синхронизации» / «ПК недоступен»), рядом кнопка «Синхронизировать сейчас». Пока приложение открыто, попытка повторяется каждые 15 секунд; в фоне опрос не идёт, но изменения, сделанные перед уходом с экрана, всё равно отправляются.

Правки делаются поверх сохранённого состояния под той же блокировкой, под которой синхронизация записывает свой результат, — иначе правка, посчитанная от копии до синхронизации, могла бы затереть пришедшие с ПК диалоги, и следующая синхронизация удалила бы их и на ПК. Черновик пишется на диск не на каждое нажатие, а через 0,6 секунды после паузы в наборе, при уходе с экрана и при выходе из аккаунта.

## Модели

| Модель | Назначение |
| --- | --- |
| A-4.5 | Самая мощная. Выбрана по умолчанию |
| V-4.4.1 | Сбалансированная |
| S-4.5 | Лёгкая |

После первого обмена название диалога пишет модель — всегда лёгкий маршрут S-4.5, какой бы ни был выбран для разговора: имя из трёх слов не стоит цены и ожидания больших маршрутов. Пока имя не пришло или запрос не удался, остаётся запасное — обрезанное первое сообщение; ошибка не показывается. Имя применяется только если к тому моменту его не изменили вручную, поэтому переименование во время запроса не затирается. `cleanTitle` снимает кавычки, префиксы вроде «Title:» и точку в конце — знак вопроса остаётся, он в названии уместен.

### Уровень размышлений

В поле ввода, перед микрофоном, стоит диск-спидометр. Его стрелка показывает выбранный уровень: Instant → Medium → High → Extra High → Ultra. Нажатие приглушает чат и выводит на месте поля ввода слайдер на пять делений. Бегунок идёт за пальцем, щёлкает на каждом делении и доводится пружиной до ближайшего. Нажатие на дорожку сразу переносит его на нужный уровень. Выбор сохраняется, синхронизируется вместе с настройками и применяется к следующему запросу. Клавиатура остаётся открытой.

| Уровень | `reasoning.effort` | `max_tokens` | Ожидание |
| --- | --- | --- | --- |
| Instant | выключено | 4096 | как раньше (90 / 120 с) |
| Medium | `medium` | 8192 | 180 с |
| High | `high` | 16384 | 240 с |
| Extra High | `xhigh` | 24576 | 300 с |
| Ultra | `max` | 32768 | 420 с |

Размышления и ответ делят один лимит токенов, поэтому глубоким уровням лимит увеличен. Если размышления всё же съели его целиком, показывается «Размышления заняли весь лимит ответа», а не «пустой ответ». Текст размышлений запрашивается с `exclude: true` и в историю не попадает. Модели в системном промпте сообщается действующий уровень.

Уровень действует только у маршрутов с `reasons = true` в `Models.kt`: сейчас это V-4.4.1 и S-4.5. Маршрут A-4.5 рассуждать не умеет. Для него запрос отправляется ровно как раньше, а панель честно пишет, что уровень действует у других моделей. В режиме O5 диск скрыт: агент работает на своих фиксированных настройках.

`LiveEffortTest` отправляет каждый уровень каждой «думающей» модели через настоящий сервис. Запуск: `$env:LUMA_LIVE_EFFORT = "1"`, затем тесты. Результат пишется в `build/effort-live-result.txt`.

Модель переключается в настройках или нажатием на её метку под полем ввода. Выбор сохраняется между запусками и применяется к следующему запросу; уже полученные ответы не меняются.

Маршруты моделей объявлены в `Models.kt` как `internal` и не выводятся в интерфейсе. Тест `nothingUserFacingNamesTheProviderOrTheRoute` следит, чтобы названия поставщиков и маршрутов не попадали в подписи моделей и тексты ошибок. Это не защита от обратной разработки: строки маршрутов видны в дизассемблированном APK и в сетевом трафике.

## Языки

Английский (`values/`), русский (`values-ru/`) и испанский (`values-es/`). По умолчанию язык берётся из системы; в настройках его можно задать вручную. Выбор хранится в настройках и применяется через `createConfigurationContext` к поддереву Compose (`Language.kt`) — процессная локаль не трогается, переопределяется только то, что рисует интерфейс.

Пер-приложенческий язык Android 13 не используется: приложение поддерживает API 26, и один путь на всех версиях предсказуемее двух. Lint предупреждает `AppBundleLocaleChanges` — это про языковые сплиты Play App Bundle; в APK все три языка лежат внутри, так что здесь предупреждение неприменимо.

Ошибки не собираются в строки внутри шлюза и вьюмодели: `ChatFailure` и `SignInFailure` несут идентификатор ресурса, а текст разрешается там, где показывается. Так сообщение всегда на том языке, который выбран сейчас, даже если ошибка возникла раньше.

`LocalizationTest` сверяет наборы ключей всех трёх файлов, разрешает каждую строку в каждом языке и проверяет, что ни в одной не всплывают названия поставщиков.

## Промпт

Каждый запрос начинается с системного сообщения (`SYSTEM_PROMPT` в `Models.kt`): ассистент — Iskra AI, отвечает на языке пользователя, не обсуждает свою реализацию. Про то, что он искусственный интеллект, а не человек, отвечает честно; под полем ввода это написано и в интерфейсе.

## Форматирование ответов

Ответы отображаются как Markdown: жирный текст, курсив, заголовки, списки, цитаты, ссылки, зачёркивание и блоки кода. Переносы строк сохранены. Кнопка копирования переносит текст без служебной разметки. Рендеринг — Markwon 4.6.2, без WebView.

## Ответы и история

Ответ приходит целиком; потоковой выдачи по сети пока нет. Готовый ответ раскрывается на экране по словам — около 40 шагов по 45 мс, так что длинный ответ ускоряется, а не тянется. Каждый шаг заново разбирает Markdown, поэтому число шагов ограничено. Пока идёт раскрытие, знак вращается, а кнопка копирования скрыта: копировать полответа незачем. Модели передаётся системный промпт и текущий диалог, включая предыдущие настоящие ответы. Другие разговоры не передаются. Старые ответы демоверсии помечаются и исключаются из контекста.

«Остановить» отменяет HTTP-запрос. «Повторить запрос» повторяет неотвеченный вопрос без дублирования. Ошибки лимитов, квоты, сети, пустого ответа и доступности модели показаны по-русски и без упоминания поставщика.

Максимум ответа на уровне Instant — 4096 токенов, на более глубоких уровнях больше (см. «Уровень размышлений»); достижение лимита помечается. Таймаут соединения — 15 секунд, чтения — 90 секунд, всего запроса — 120 секунд; с включёнными размышлениями ожидание дольше.

## Оформление

Цветовые роли Material 3 генерируются из тональных палитр: акцент задан тоном и насыщенностью в CIELCh, тон роли равен CIE L\*, насыщенность снижается до попадания в sRGB (`Theme.kt`). Поэтому контраст одинаков для всех акцентов, а нейтральные поверхности окрашены в тон акцента. Доступны Лаванда, Мята, Персик и «Обои» — динамические цвета Material You на Android 12+.

Тип-шкала и шкала форм заданы целиком, компоненты берут скругления из `MaterialTheme.shapes`. «Крупный текст» масштабирует всю шкалу.

### Движение

Экран входа оформлен как экран первичной настройки: поле четырёхлучевых звёздочек Material (`Sparkles.kt`), дышащее сияние за знаком и каскадное появление знака, заголовка, подписи, кнопки и сноски со сдвигом по времени. Все звёздочки питаются от одной анимации — каждая берёт свою фазу из синуса, поэтому на экране работает одна анимация и один проход отрисовки.

Контейнер знака перетекает по семейству expressive-фигур Material 3 — печенье, клевер, солнце, цветок, пухлый ромб, мягкая вспышка — и медленно поворачивается, так что каждая новая форма приходит под другим углом. Знак внутри компенсирует поворот и остаётся вертикальным.

Фигуры лежат в `Shapes.kt`. Material отдаёт их как `MaterialShapes`, но этот объект появился в material3 1.5, которому нужен более новый Android Gradle plugin, чем стоит в проекте. Поэтому они пересобраны на `androidx.graphics:graphics-shapes` — той самой библиотеке, на которой официальный набор и определён, тем же построением через `star()` и `RoundedPolygon()`, и морфятся точно так же. Каждый кадр вписывается в одну опорную рамку, посчитанную заранее прогоном по всем морфам цикла. Мерить границы на каждом кадре нельзя: фигуру начинает водить и «раздувать», потому что промежуточная форма выходит за пределы обеих исходных.

Пустое состояние чата и аватар в настройках используют статичные фигуры из того же семейства — печенье и клевер. Морф там намеренно не запускается: эти экраны должны доходить до состояния покоя для скриншотных тестов.

Пока пишется ответ, знак Лумы вращается как вентилятор — ровным ходом, оборот за 1,6 секунды. Четыре лепестка стоят через 90°, поэтому оборот подобран так, чтобы читаться одним плавным движением, а не четырьмя рывками.

Внизу бокового меню две плавающие кнопки, как у больших ассистентов (`DrawerUi.kt`). Слева «пилюля» «Новый диалог», справа аватар аккаунта: инициал на клевере, том же, что в настройках. Аватар открывает настройки. Список диалогов прокручивается под кнопками и растворяется за ними. При каждом открытии меню кнопки по очереди поднимаются на место.

Заголовок пустого чата начинается с «С чего начнём?». Каждые 4,5 секунды строка уезжает вниз и гаснет, а сверху на пружине приезжает короткая философская мысль. Мысли берутся из `R.array.empty_thoughts` (`thoughts.xml`, по девять на каждый язык) в случайном порядке, без повторов, пока не пройдут все. Под заголовок всегда отведено две строки, чтобы знак и подпись не прыгали. Пока открыта клавиатура или в системе выключены анимации, заголовок стоит на месте. В O5 заголовок свой и не меняется.

Нажатие на знак над заголовком сжимает форму и доворачивает знак на четверть оборота с пружиной. Лепестков четыре, так что он встаёт как стоял. Пасхалка: пять быстрых нажатий, каждое не позже 0,7 с после предыдущего (`TapStreak`). Знак раскручивается как вентилятор — восемь оборотов за 3,2 с с долгим выбегом. Форма подрастает и окрашивается в третичный цвет, в начале и в конце — тактильный отклик. Скорость ограничена так, чтобы на пике лепестки не казались крутящимися назад, как колёса в кино.

В остальном приложении: пружинное появление пустого состояния, перекрёстное затухание иконки «отправить/остановить» и затухание метки модели при переключении.

Тактильный отклик разведён по типам Material вместо одного «бз» на всё: `Confirm` на отправку, `SegmentTick` на выбор модели, языка, темы и акцента, `ToggleOn`/`ToggleOff` на переключатели, `ContextClick` на навигацию. Раскрытие ответа щёлкает `SegmentFrequentTick` примерно восемь раз в секунду — так это читается как печать, а не как гудение. Всё это под тем же переключателем «Тактильный отклик».

`motionEnabled()` читает `Settings.Global.ANIMATOR_DURATION_SCALE`: если анимации отключены в системе, звёздочки, морф фигур и вращение знака замирают в статичном виде.

Бесконечные анимации не дают Compose перейти в состояние покоя, поэтому тест экрана входа переводит часы в ручной режим (`mainClock.autoAdvance = false`) вместо ожидания простоя.

## Хранение и передача данных

История, настройки и запись об аккаунте хранятся в приватных SharedPreferences. Резервное копирование отключено.

**Ключ доступа встроен в APK** (`EmbeddedKey` в `Credentials.kt`). XOR-пад убирает строку из плоского дампа `strings`, но это не защита: ключ извлекается декомпилятором за минуты, и все запросы владельца APK оплачиваются им. Ключ нужно менять на openrouter.ai всякий раз, когда сборка выходит за круг доверенных людей.

`AndroidCredentials` — шифрование ключа через Android Keystore — оставлен в коде и покрыт тестами на случай возврата к ключу на стороне пользователя, но в продакшене сейчас не используется.

При отправке контекст текущего диалога передаётся по HTTPS поставщику выбранной модели. Лимиты и доступность определяются им же.

## Сборка

Откройте папку в Android Studio. Требуются JDK 17, Android SDK Platform 35 и Build Tools 35.0.0.

```powershell
.\gradlew.bat assembleDebug
.\gradlew.bat testDebugUnitTest lintDebug
```

macOS / Linux: `chmod +x gradlew`, затем `./gradlew` вместо `gradlew.bat`.

## Структура

- `Models.kt` — три модели, их маршруты, продуктовые имена и системный промпт Iskra AI.
- `IskraReference.kt` — справочник линейки Iskra, который уходит в промпт.
- `HistorySync.kt` — клиент синхронизации с пиннингом сертификата, локальный кэш и слияние.
- `SyncConfig.kt` — токен, вшитые адреса и адрес ПК, заданный на телефоне.
- `Auth.kt` — вход через Google и локальное хранение аккаунта.
- `Language.kt` — три языка и переключение локали для поддерева Compose.
- `Sparkles.kt` — поле мерцающих звёздочек и проверка системного отключения анимаций.
- `Shapes.kt` — expressive-фигуры Material 3 и морфинг между ними.
- `OpenRouterGateway.kt` — HTTP, контекст, отмена, разбор ответа и ошибок.
- `Credentials.kt` — встроенный ключ, Android Keystore и зависимости приложения.
- `ChatData.kt` — ViewModel, хранение, миграция, состояния запросов и повторы.
- `MainActivity.kt`, `SignInScreen.kt`, `SettingsScreen.kt`, `Theme.kt` — интерфейс.
- `OpenRouterGatewayTest.kt` — MockWebServer, отмена, ошибки, маршруты, промпт, миграция.
- `NativeUiTest.kt` — UI и рендеринг Robolectric / Roborazzi, без реальных сетевых вызовов.
- `LocalizationTest.kt` — полнота переводов, разрешение строк во всех языках, отсутствие утечек маршрутов.
- `ChatFlowTest.kt` — instrumented-проверки входа, настроек и навигации.

Результаты и ограничения фактической проверки — в `Проверка.md`.
